# Information Architecture

## Mobile primary navigation
The operational mobile experience should prioritize:
- Home
- Assets
- Request / My Requests
- Activity/Profile as appropriate

A prominent create/request action may be used if it improves speed, but it must not replace asset-first booking logic.

## Mobile secondary/admin
Master Data, approval configuration, dense reports, and user mapping should not crowd primary mobile navigation. Authorized users may access them through secondary navigation; key approval actions remain mobile-friendly.

## Desktop navigation
Suggested top-level structure:
- Home
- Inventory / Assets
- Requests
- Reports
- Administration
  - Brand
  - Category
  - Warehouse & Vendor
  - Division
  - Users
  - User Mapping
  - Approval Matrix

## Principle
Desktop and mobile use the same domain and permissions but may use different composition and navigation patterns.
