# Product Principles

1. **Find before producing.** The first job is to expose reusable existing assets.
2. **Answer, then detail.** Cards and details should immediately answer availability, location, age, and condition before secondary metadata.
3. **Booking is attached to a real asset.** A request should preserve which asset/item is being requested and for what period/context.
4. **Operational truth beats presentation.** Current location/status must be maintained reliably.
5. **Lifecycle is decision support.** Old or poor-condition assets should not look equally usable simply because quantity exists.
6. **Mobile is first-class.** Mobile is designed intentionally; it is not a compressed desktop.
7. **Action over dashboard theater.** Home surfaces approvals, overdue returns, review-due assets, and useful shortcuts before decorative analytics.
8. **Governed vocabulary.** Brand/category/location/division/approval rules should come from managed records where appropriate.
9. **Progressive disclosure.** Keep common mobile actions simple; expose administration and dense tables where they are appropriate.
10. **No accidental scope expansion.** Event context does not turn AssetHub into an event-planning, budgeting, or procurement platform.
