# Post-Prototype User Feedback - Historical Input

**Input record only. V2 specifications contain the interpreted final requirements.**

After reviewing the prototype, users asked for the application to become the new home for event-asset booking and management.

The feedback organized the product around:
- Master Data
- Inventory
- Form Request / booking
- Report

Master Data feedback included governed entities such as:
- Brand
- Category
- Warehouse & Vendor
- Division
- User
- User Mapping
- Approval Matrix

V2 interpretation:
- Inventory remains the source of truth.
- Booking/request becomes a core workflow.
- Master Data becomes explicit governance.
- Reporting becomes operational listing/visibility.
- Asset age/lifecycle remains even though it was less prominent in the feedback.
- The app does not expand into budget/procurement/full event management.
