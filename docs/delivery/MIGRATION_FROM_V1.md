# Migration from V1 Prototype

## Treat V1 as
- Product intent reference
- Interaction/visual reference where still useful
- Source of sample data concepts
- Evidence of previously explored flows

## Do not treat V1 as
- Production architecture
- Final navigation
- Final responsive behavior
- Final data model
- Final permission model
- Final design system

## Preserve
- Core asset visibility
- Search/filter intent
- Internal/external location concept
- Asset age/lifecycle value
- Request/history direction
- Useful prototype interaction ideas

## Refine/rebuild
- Mobile-first navigation
- Booking as core workflow
- Formal master data
- Approval matrix and permissions
- Action-oriented home
- Component architecture/design tokens
- Persistent data/auth/audit
- Operational reporting

## Migration rule
Do not port prototype code line-by-line merely to preserve appearance. Reimplement behavior against V2 domain and design rules.
